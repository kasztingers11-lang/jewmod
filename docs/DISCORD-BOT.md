# Neoperro Discord panel and tickets

The bot uses signed HTTP interactions on `/api/discord-bot`, with deferred private replies for operations that contact storage or providers. Background work uses Vercel waitUntil. No Gateway connection or message monitoring process is needed; an HTTP-only bot can display as offline while its buttons and commands work.

The public license panel offers Link license, My license, Get key, Get script, Reset HWID and Open dashboard. License actions use the signed Discord member ID. Claiming reuses the website’s license service and permanent Discord association. The existing provider device-reset policy and 24-hour cooldown are enforced. Keys and scripts are returned only through private interaction responses. Form values, interaction tokens and bot tokens are not stored in receipts or application logs.

The support panel offers General support, License help and Report a problem. A form creates a channel visible to the opener, the configured support role and the operator; Discord administrators retain their platform access. Only one open ticket is allowed per account. Support can claim, export and reopen; the opener or support can confirm closure. Closing exports a plain-text transcript to the configured logs channel and makes the opener’s channel permissions read-only. Channels are preserved. Reopening restores access. No automatic channel deletion is implemented.

Transcripts contain available messages and attachment links; files are not downloaded. Recognizable script_key assignments and Discord webhook URLs are redacted, which does not guarantee arbitrary secrets pasted into chat can be recognized. Exports are bounded to the latest 1,000 messages or about 1.8 MB of source message data. Any truncation is explicitly labelled. Discord remains the message and transcript store. Private ticket metadata expires 90 days after closure, receipts after 15 minutes and action counters after one minute.

## Configuration

Public application, key, channel and support-role identifiers live in `server/discord-bot-api.mjs`. Credentials belong in Production-only Vercel variables: DISCORD_BOT_TOKEN and DISCORD_BOT_SETUP_SECRET. The runtime also uses the existing private Redis variables, NEOPERRO_SESSION_SECRET, NEOPERRO_OWNER_DISCORD_ID and FLOWAUTH_API_KEY. DISCORD_BOT_GUILD_ID is mandatory for every user-facing action. A missing or different server fails closed. Commands are registered only in that guild. Discord’s Public Bot setting must be off; its API can verify the setting but does not expose an edit field for it.

The private `/api/discord-bot-setup` endpoint accepts signed POST JSON with exactly one action: inspect, configure or test-ticket. Authentication uses X-Neoperro-Setup-Timestamp (Unix milliseconds) and X-Neoperro-Setup-Signature (`sha256=` plus HMAC-SHA256(timestamp + '.' + raw body) using DISCORD_BOT_SETUP_SECRET). Credentials must not be included in URLs or committed files. Inspect checks the application identity, discovers the server from the three supplied channels, validates roles and reports privacy and permissions. Configure sets the HTTP interaction endpoint, guild-only commands and existing panel messages, and creates a dedicated private ticket category if needed. Repeated configuration updates the bot’s messages instead of posting new copies.

To lock and reopen channels, the bot needs Manage Permissions in its ticket category. This can be granted there without giving global role management. Message Content Intent must be enabled in the Developer Portal for complete transcript contents. The setup test refuses to close an existing owner ticket; it creates a clearly labelled synthetic ticket only when the owner has none open.

`DISCORD_BOT_ALERTS=true` routes the existing signed FlowAuth receiver through bot messages in the configured logs channel. Its comparison state and change-only behavior are preserved. Log delivery checks that the channel belongs to the allowed server and is restricted to permitted staff, the owner and the bot; administrators retain platform access. Unknown integration roles and individual access grants do not bypass the privacy check. Bot alerts add an owner-only license-details button. No full license key or raw HWID is included in alerts. The webhook transport remains available until bot delivery has been verified.

## Validation limits

Offline tests cover exact signature bytes and freshness, foreign-server rejection, private deferred responses, identity-bound license calls, explicit reset confirmation, owner-only lookup, interaction deduplication, permission overwrites, one-ticket concurrency, claim/close/reopen, transcript redaction, unsafe log-channel rejection and fixed Discord API destinations. Native Discord behavior must also be verified after deployment. A successful API post is not proof that another member’s Discord client renders a private response correctly. Upstream timeouts can leave an operation uncertain; channel creation and receipts deliberately avoid blind duplicate creation.
